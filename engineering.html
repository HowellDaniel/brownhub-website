    How it is built

    The parts under the page

    Chosen because they are dependable and affordable to run in Ghana, not because they are fashionable.

    Interface

    Hand-written HTML, CSS and JavaScript. No page builder, no plugin stack to expire, nothing that phones home to a licence server.

    Data & accounts

    A managed Postgres database with row-level security, so a signed-in client can only ever read their own records. Login by phone code or email.

    Server side

    Small edge functions for the work that must not happen in the browser: signing payments, holding API keys, relaying messages.

    Payments & messaging

    Paystack for card, mobile money and Apple Pay; SMS codes for login; WhatsApp deep links so an order can continue in a chat.

    Delivery

    Static hosting on a global content network, a service worker for offline use, and a manifest so the site installs to a home screen.

    Quality & care

    Contrast checked to AA in both themes, motion that stops when the visitor asks for it, backups taken, and every page measured for errors after each change.

    Questions people ask

    Before you commission a build

    Quick answers on how the engineering side works.

    Do you write the code, or assemble it from templates?

    Written by hand. Templates and page builders are cheap on day one and expensive in year three, when the plugin you rely on stops being maintained. Hand-built pages carry nothing you did not ask for, which is also why they load quickly on a modest data plan.

    Can you connect the tools I already use?

    Usually yes. Payments through Paystack, orders into WhatsApp or email, records into a database your staff log in to, and links out to the platforms you already run. Send us the list of what is in place and the quote says which parts connect.

    Will it work on a slow connection or an old phone?

    That is a build requirement, not an afterthought. Pages are kept light, tested on real phones before launch, and given an offline mode so a weak signal shows you something useful instead of a blank screen.

    Who owns the website when it is finished?

    You do — the domain, the hosting account, every login and the source files. We hold copies while we maintain the site, and hand them over the day you ask for them.

    How do you keep it secure?

    Row-level access on the data, secrets kept on the server and never in the page, a content policy that refuses injected script, rate and bot gates on every form, and a published security page that states what we collect and what we never store.

    How long does a build take?

    It depends on the number of pages and features, and whether the content already exists. The date is part of the written quote, and if the brief changes the quote is revised before further work starts — nothing runs on and on without a number attached.

    What happens after launch?

    Hosting, updates, backups and small changes are what the support covers. Bigger work — a new module, a booking system, a client area — starts from a fresh quote, the same way the first build did.
